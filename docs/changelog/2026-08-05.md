# 2026-08-05 开发日志

## 新增站点适配：UK / DE / FR / IT / ES

### 抓取引擎适配

**价格/评分格式（DE/FR/IT/ES）**
- 欧洲站点使用逗号小数分隔符（`53,54€`），`_base` 的 `extractPrice` 用 `match(/[\d,]+\.?\d*/)` 只能提取到 `53`
- 各站点新增 `parsers.js`，将 `53,54` → `53.54` 后再提取数字
- 评分本地化格式各不同：DE `von 5 Sternen`、FR `sur 5 étoiles`、IT `su 5 stelle`、ES `de 5 estrellas`，各站点独立覆盖 `extractRating`

**库存文本归一化**
- 业务方确认使用本土语言对比，DE/FR/IT/ES 各建 `normalizers.js` 覆盖 `normalizeStock`，直接返回原文不做英文转换
- UK 使用英文，`_base` 归一化逻辑可直接使用

**`index.js` stripNodeGuards**
- 新增 UK/DE/FR/IT/ES 到正则白名单，避免站点导出对象被误删

### 配送地初始化（最大技术难点）

**问题背景**
- 中国 IP 访问 Amazon EU 站点，默认配送地为中国，价格显示 CNY，且部分商品显示「无法配送到您的地址」
- 需要在抓取前将配送地切换到目标站点的本地邮编

**各站点差异**

| 站点 | 机制 | 原因 |
|------|------|------|
| US/CA/AU/MX | AJAX POST `/gp/delivery/ajax/address-change.html` | 未登录 session 有 `anti-csrftoken-a2z`，旧接口有效 |
| ES/IT/FR | 同上 | 旧接口有效，实测 IT 返回 `isAddressUpdated:1` |
| UK/DE | DOM 点击地址弹窗 | 未登录 session 无 `anti-csrftoken-a2z`，只有 `glow-validation-token`；旧接口被重定向到内部域名（`ERR_NAME_NOT_RESOLVED`）；新接口（`/portal-migration/hz/glow/address-change`）返回 200 但不生效 |

**UK/DE DOM 点击方案细节**
- 初始化窗口加载**商品页**（不是首页）——Cookie 弹窗只在商品页渲染，首页不出现
- 先等待并处理 Cookie 弹窗（`#sp-cc-accept`），等弹窗消失后继续
- 点击 `nav-global-location-popover-link` → 等待 `GLUXZipUpdateInput` 出现 → 填邮编 → Apply → 等 Confirm 按钮出现 → 点击 Confirm → 页面自动刷新
- 初始化窗口定位到屏幕外（`x: -900, y: -700`），`skipTaskbar: true`，用户无感知
- 使用全局互斥锁（`initLock`）保证 UK/DE 串行初始化，避免并发触发 Amazon `ERR_ABORTED`

**Cookie 同意弹窗**
- UK/DE/ES/IT/FR 首次访问均会弹出 Cookie 同意弹窗，必须接受后才能正常操作地址弹窗和 AJAX 接口
- 所有站点初始化时统一加载商品页，Cookie 弹窗由统一逻辑处理
- 等待弹窗消失（轮询）而不是等页面加载，更可靠

**session Cookie 复用**
- 初始化成功后 session Cookie（包含配送地）由所有同域名窗口自动共享
- 第二次及后续巡检检测 `session-id` + `i18n-prefs` Cookie 是否已存在，存在则跳过初始化，速度从 ~2 分钟缩短到 ~30 秒

**ERR_ABORTED 重试机制**
- 并发任务同时触发初始化时，Amazon 可能断开连接
- `initDeliveryZip` 失败后最多重试 3 次，每次间隔 3 秒
- `pendingSiteInit` Map 保证同一站点同时只有一个初始化 Promise

### 币种显示修复

- 中国 IP 访问 EU 站点默认显示 CNY

- 币种由 `i18n-prefs` Cookie 决定，通过 `session.cookies.set()` 直接写入，绕过需要登录的 `/customer-preferences/api/xop` 接口
- 已验证站点：UK=GBP，DE/FR/IT/ES=EUR

### 巡检逻辑优化

**每次开始巡检都是全新任务**
- 移除「继续巡店」逻辑：之前上次结果残留时，再次开始只会跑未完成的任务，导致业务反馈「43个ASIN只跑了2个」
- 现在每次点「开始巡店」确认后立即清空上次结果（含 store），全量重跑

**按钮文字统一**
- 停止按钮改为「取消」，语义更准确
- 任何状态下开始按钮始终显示「开始巡店」，移除「继续巡店」状态

### 选择器调试器增强

- 新增「扫描区域」功能：点击任意容器元素，递归输出所有子节点的选择器和值

- 支持长文本展开/收起预览
